## Contratos e ficheiros antes de implementar

Domain em src/modules/ai-assistant/domain/model-input.ts: AiQuestion.text mantém significado após trim,1..1000 bytes UTF-8, rejeita tipo não string, surrogate isolado e controlos C0/C1 exceto tab/CR/LF. SourceSentence props {id,paragraph,start,end,text}: ID ASCII kebab1..64, paragraph inteiro positivo seguro, offsets inteiros seguros0<=start<end e diferença igual ao comprimento em codepoints do texto exato, não reescrito; texto não vazio/sem surrogate isolado. Contexto1..32 frases/IDs únicos/total até2400 bytes, origem/ordem preservadas. SourceSelection(citationId,context) só aceita null ou um ID do contexto, imutável; status derivado supported/insufficient-evidence e frase exata/null. Nenhum conhecimento bíblico/histórico inventado.

Application ports.ts: EmbeddingsPort.embed({purpose:source|question,texts},signal?)→EmbeddingBatch {vectors,provenance,usage}; LlmProviderPort.select(AiQuestion,readonly SourceSentence[],signal?)→GeneratedSelection {selection,provenance,usage}. signal é AbortSignal padrão, sem SDK. Embeddings até16 textos não vazios/até4000 bytes cada; query recebe prefixo do perfil, texto de fonte preservado. EmbeddingBatch tem vetores1024 finitos/normalizados; TokenUsage usa inteiros não negativos/prompt>0, soma real total; provenance modelo/hash/runtime/prompt/configuração efetiva. errors.ts distingue AiResultRejectedError/AiUnavailableError/AiTimeoutError, sem segredo/corpo bruto na mensagem pública. Não receber owner/token/URL/caminho/modelo pelo port de caso de uso.

Infrastructure prevista: prompt.ts conserva prefixo/JSON separadores exatamente como perfil, constrói apenas contexto não confiável/enum de IDs; protocol.ts faz validação Zod/uso/dimensões/norma/finish/ID-null/bounds; local-model-provider.ts implementa ports com HTTP nativo; native-runtime.ts gere artefactos/processo/slot/saúde/cancelamento/finally; runtime-profile.ts lê/verifica perfil/pins/caminhos confiáveis. Tipos externos ficam aqui. Ficheiros de teste correspondentes em test/unit/ai-assistant e integrações/prova real identificadas. Interfaces/skeletons mínimos executáveis podem permitir RED de negócio, sem erro de importação/sintaxe contado como RED.

Runtime: distribuição assinada já executada, apenas processo direto criado pelo agente/aplicação; modelo sequencial/auth key-file/loopback/no shell/windowsHide/ambiente allowlist/offline/no-context-shift/2threads/parallel1. Chave nunca em argv/env herdado/log; modelos/binários pinados. Exclusão mútua de sessão, slot ocupado indisponível, sem retry/fallback/filas. Lock exclusivo próprio no diretório AI impede duas instâncias da aplicação/CLI de carregar modelos simultaneamente; lock de crash não é apagado cegamente, recuperação só após identidade/liveness comprovadas/runbook. finally/libertação limpa só recurso próprio; encerramento normal/cancelamento têm teste. Crash forçado do SO exige procedimento operacional, sem prometer finally após morte do processo.

HTTP só para a porta da própria sessão, redirect recusado, auth por Bearer interno, corpo limitado64KiB geração/4MiB embeddings, timeout cobre leitura. Readiness180s/inferência120s/encerramento10s, sem ampliar para obter aprovação. Conferir template/tokenizer real e orçamento antes de inferir; excesso/JSON inválido/ID desconhecido/finish não stop rejeita, falha técnica/timeout mantém erro próprio. Sucesso de endpoint/protocolo técnico não é evidência semântica. Sem variável .env do utilizador alterada.
