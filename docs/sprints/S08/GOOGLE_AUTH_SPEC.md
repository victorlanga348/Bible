# S08-T008 — Google Sign-In após a release local

Aceite por decisão delegada2026-10-30 antes de código, mediante pedido explícito para finalizar login Google configurado no .env. Adenda de escopo: Google estava excluído da release84db8fe; este incremento mantém ambiente pessoal local, seis módulos, dados/owners/CLI existentes e acrescenta autenticação Google. Sem frontend completo/publicação remota/novo pacote/migração/API Google adicional. Fecho anterior comprova apenas a sua revisão.

Configuração: GOOGLE_CLIENT_ID opcional, web client `<digits>-<identifier>.apps.googleusercontent.com`, ASCII até256caracteres sem espaços; inválido impede arranque com erro genérico. Se configurado exige jwtSecret existente>=32bytes. Sem client, backend anterior funciona e rotas Google503GOOGLE_AUTH_UNAVAILABLE. Não exige/consome client secret e não altera .env.

GET /auth/google entrega página local mínima/botão GSI oficial. Desafio aleatório32bytes/base64url43 ligado a nonce do Google e cookie HttpOnly/SameSiteStrict/Path=/auth/google/MaxAge300. Desafios em memória por instância,TTL300s/até128pendentes para limitar memória, sem persistência/sessão nova; expirar antes de recusar capacidade503. Desafio consumido atomicamente após verificar Google e antes de emitir JWT; replay401. Reinício invalida desafios.

GET /auth/google/client.js entrega callback estático que envia JSON ao mesmo backend, guarda tokens só em memória/texto do navegador para cópia deliberada e confirma acesso privado em /auth/me. Não usar localStorage/query/log para token. Cache-Control:no-store/CSP/COOP/referrer-policy apropriados a GSI/localhost. Client ID público só na resposta runtime, nunca valor em código versionado. Browser usa http://localhost:PORT; Console Google deve autorizar localhost e localhost:PORT.

POST /auth/google recebe JSON estrito `{credential:string,csrfToken:string}`. Credential JWT ASCII3segmentos/1..16384bytes; csrfToken base64url43. Exigir Content-Type JSON, Origin exatamente http://localhost:PORT ou http://127.0.0.1:PORT, cookie único igual ao desafio/body, ainda válido.401AUTH_REQUIRED para origem/CSRF/assinatura/claims/replay inválidos;400VALIDATION_ERROR para schema;503GOOGLE_AUTH_UNAVAILABLE para ausência/capacidade/JWKS indisponível. Filtro próprio, sem mudar erros de outros contratos; nenhuma credencial/claim/email/SQL nos diagnósticos.

JOSE6.2.13 existente verifica RS256 somente/JWKS Google fixo https://www.googleapis.com/oauth2/v3/certs,timeout5s/cache da biblioteca, sem override HTTP/env. iss accounts.google.com ou https://accounts.google.com; aud string exatamente client; sub ASCII1..255; iat/exp inteiros seguros/exp>iat/idade máxima3600s/tolerância30s; nonce exatamente desafio; azp, se presente, igual client. Identidade somente sub, nunca email/nome/email_verified como substituto. Owner determinístico `google-`+SHA256(sub)base64url,50caracteres. Não armazenar perfil/email/ID token nem ligar contas antigas automaticamente.

Sucesso200 `{accessToken,tokenType:'Bearer',expiresIn:3600}`, JWT HS256 local existente por1h; limpar cookie do desafio/cache-no-store. GET /auth/me usa guard Bearer existente e devolve `{ownerId}` opaco. Google novo vê só seus recursos; owners locais e dados prévios preservados. Cookies Google não autorizam recursos privados, apenas Bearer local.

Provas: TDD causal por configuração/verificador/desafios/serviço/HTTP; RSA real/JWKS técnico identificado/claims negativas, Nest/Supertest e PostgreSQL reais/owner isolado. Fixtures de protocolo não são Google. Verificar discovery/JWKS/JS oficiais por rede real sem credenciais. Prova de conta exige clique/consentimento do utilizador no navegador; guardar só resultado sanitizado e acesso privado. Ausência dessa prova é BLOCKED, não PASS. Sete gates da nova revisão/CI/cobertura/mutação/revisão obrigatórios antes de DONE.
